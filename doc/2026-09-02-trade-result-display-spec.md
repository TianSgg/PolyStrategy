# 天气 Sweep 交易结果前端展示规范

## 1. 目的

交易结束后，列表中的状态需要区分两类信息：

1. 交易生命周期是否已经结束。
2. 交易为什么结束，以及是否存在需要关注的异常。

当前每条交易使用两个徽标展示：

```text
[已结束] [正常退出]
```

两个徽标职责不同，不能使用同一套颜色规则。

## 2. 两个徽标的职责

### 2.1 第一个徽标：生命周期状态

第一个徽标只表示交易当前所处的生命周期，不表示交易是否成功，也不表示是否发生异常。

| 生命周期 | 文案 | 颜色 |
|---|---|---|
| `entry` | `入场中` | 蓝色 |
| `exit` | `出场中` | 琥珀色 |
| `closed` | `已结束` | 灰色 |

当交易进入 `closed` 状态后，第一个徽标始终显示为：

```text
[已结束]
```

并始终使用灰色。第二个结果徽标不能改变第一个徽标的颜色。

### 2.2 第二个徽标：结束结果

第二个徽标只在生命周期已经结束时显示，根据 `close_reason` 决定文案和颜色。

## 3. 颜色含义

| 颜色 | 含义 | 使用范围 |
|---|---|---|
| 绿色 | 正常完成或有部分成交但未构成异常 | 买入和卖出按预期完成，部分成交但最终无异常 |
| 灰色 | 未执行或中性结束 | 资金不足、没有成交、跳过、普通超时 |
| 琥珀色 | 有结果但需要注意，不一定是系统故障 | 止损、卖出未完成、低于最小下单量 |
| 红色 | 执行或系统异常，需要重点处理 | 接口报错、程序错误、成交校准失败、订单未清、强制退出 |

红色只表示明确的执行或程序异常，不能仅因为交易没有形成完整成交就使用。

## 4. 结束情况展示规则

### 4.1 正常完成

| 数据条件 | 展示内容 | 颜色 |
|---|---|---|
| `close_reason=normal_exit` | `正常退出` | 绿色 |

示例：

```text
[已结束] [正常退出]
```

### 4.2 没有执行交易

| 数据条件 | 展示内容 | 颜色 |
|---|---|---|
| `close_reason=no_cash` | `资金不足 · 未下单` | 灰色 |
资金不足表示策略没有实际建立交易，不属于程序故障，不使用红色。

### 4.3 买入没有成交

| 数据条件 | 展示内容 | 颜色 |
|---|---|---|
| `close_reason=timeout_no_fill` 且买入份额为 0 | `入场超时 · 无成交` | 灰色 |
挂单后没有成交属于市场执行结果，不等同于接口或程序错误。

### 4.4 买入部分成交

如果买入只成交了一部分，但没有产生系统异常，应显示为绿色，不显示红色或琥珀色。

推荐展示：

```text
[已结束] [买入部分成交]
```

颜色使用绿色。实际成交数量通过交易详情中的 `entry_shares / entry_order_size` 展示，例如：

```text
买入 15/20
```

如果部分成交后已经正常卖出，则最终结果优先显示：

```text
[已结束] [正常退出]
```

### 4.5 止损退出

| 数据条件 | 展示内容 | 颜色 |
|---|---|---|
| `close_reason=stop_loss` | `止损退出` | 琥珀色 |

止损是策略主动执行的风险控制动作，不代表程序故障，因此不使用红色。

### 4.6 卖出未完成

如果卖出流程结束时没有完全清理仓位，但没有明确接口或程序异常，显示为：

```text
[已结束] [卖出未完成]
```

颜色使用琥珀色。

以下情况属于需要注意但不自动使用红色：

| `close_reason` | 补充文案 | 颜色 |
|---|---|---|
| `exit_order_unfilled` | `仓位未清` | 琥珀色 |
| `dust_position` | `低于最小下单量` | 琥珀色 |

### 4.7 强制退出

| 数据条件 | 展示内容 | 颜色 |
|---|---|---|
| `close_reason=force_exit` | `强制退出` | 红色 |

强制退出需要用户或系统主动介入，不论最终是否有成交，都使用红色进行提醒。

### 4.8 接口或程序异常

明确的接口、程序、订单处理或成交校准异常使用红色。

| `close_reason` | 展示内容 | 颜色 |
|---|---|---|
| `buy_placement_failed` | `执行异常 · 买入挂单失败` | 红色 |
| `sell_placement_failed` | `执行异常 · 卖出挂单失败` | 红色 |
| `sell_fill_parse_error` | `执行异常 · 成交解析失败` | 红色 |
| `fill_reconcile_failed` | `执行异常 · 成交校准失败` | 红色 |
| `buy_cancel_failed` | `执行异常 · 买单撤单失败` | 红色 |
| `sell_cancel_failed` | `执行异常 · 卖单撤单失败` | 红色 |
| `tick_refresh_failed` | `执行异常 · tick 刷新失败` | 红色 |
| `unknown_failure` | `执行异常 · 未知错误` | 红色 |

`close_reason` 必须来自 trade/event 设计文档中的平铺枚举。未知原因按中性灰色展示，并记录日志供排查；不再根据已删除的 `trade_outcome` 或 `failure_reason` 推断颜色。

## 5. 判断优先级

前端计算第二个徽标时按以下顺序判断：

1. `close_reason=no_cash`：灰色，显示未执行。
2. `close_reason=force_exit`：红色，显示强制退出。
3. `close_reason` 属于系统异常集合：红色，显示执行异常和具体原因。
4. `close_reason=normal_exit`：绿色，显示正常退出。
5. `close_reason=timeout_no_fill` 或 `close_reason=market_settled`：灰色，显示自然结束。
6. `close_reason=stop_loss`、`dust_position` 或 `exit_order_unfilled`：琥珀色，显示需要关注的业务结果。
7. 其他未知结束原因：灰色，避免未知状态直接制造红色告警。

## 6. 字段职责

| 字段 | 用途 |
|---|---|
| `phase` | 决定第一个徽标是入场中、出场中还是已结束。 |
| `close_reason` | 决定交易以什么业务原因结束，以及第二个徽标的颜色。 |
| `entry_*` / `exit_*` | 在详情中展示成交数量、金额、均价和剩余仓位。 |

## 7. 典型示例

### 余额不足

```text
[已结束] [资金不足 · 未下单]
```

第一个徽标灰色，第二个徽标灰色。

### 买入挂单后没有成交

```text
[已结束] [入场超时 · 无成交]
```

第一个徽标灰色，第二个徽标灰色。

### 正常完成

```text
[已结束] [正常退出]
```

第一个徽标灰色，第二个徽标绿色。

### 卖出接口报错

```text
[已结束] [执行异常 · 卖出挂单失败]
```

第一个徽标灰色，第二个徽标红色。

### 强制退出后仍有仓位

```text
[已结束] [强制退出 · 仓位未清]
```

第一个徽标灰色，第二个徽标红色。

## 8. 实现位置

当前前端统一在以下文件中生成交易状态和结果徽标：

```text
frontend/src/tradePresentation.ts
```

`SweepTrades.tsx` 和 `StrategyDashboard.tsx` 都应复用 `lifecycleBadge()` 与 `exitBadge()`，不要在页面组件中单独实现颜色判断。

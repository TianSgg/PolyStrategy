# 跟单配置仓位历史曲线

## Summary
新增按 `config_id + asset_id` 记录 leader/follower 仓位历史的能力，用于在跟单配置页查看指定时间段曲线。仓位口径采用“leader 钱包真实仓位 + follower 钱包真实仓位”；归一化展示时只把 leader 仓位乘以该配置的 `share_ratio`，用于和 follower 实际仓位对齐比较。历史从功能上线后开始记录，不从旧订单回填。

## Key Changes
- 新增仓位历史表，记录快照而不是只记录 delta：
  - 关键查询字段：`config_id`、`asset_id`、`created_at DATETIME(3)`。
  - 原始字段保留：leader/follower 地址、`share_ratio`、leader 仓位、follower 仓位、follower pending buy/sell、事件来源、side、事件 size/price、order_id、leader_tx_hash、`raw_context TEXT`。
  - 加索引：`(config_id, asset_id, created_at)`，并提供手动迁移 SQL；不挂启动自动迁移。
- 新增 `copy_trading_config_assets` 轻量索引表：
  - 主键为 `(config_id, asset_id)`，记录 `last_seen_at`。
  - `record_position_history` 写快照时同步 upsert 该表，避免前端 asset 选择框从历史大表实时聚合。
  - 新增手动迁移 SQL，会从已有 `copy_trading_position_history` 回填当前 config-asset 列表。
- 后端记录逻辑：
  - 新增统一 helper，例如 `_record_position_snapshot(config, asset_id, source, ...)`，从当前内存缓存读取 leader/follower/pending，并异步落库。
  - 在 leader 信号更新后，仅为该 leader 下 enabled config 记录 `leader_signal` 快照。
  - `_handle_buy/_handle_sell` 下单入口不记录仓位历史；无论返回 `live`、`matched`、`delayed` 还是 `error`，都只维护订单、pending、allowance 和本地状态。
  - 在 follower `trade CONFIRMED` 后，根据 order_id 查 config 并记录 `follower_trade_confirmed` 快照；如果订单已在下单入口按 `matched` 做过本地仓位更新，则跳过重复仓位更新，但仍记录 confirmed 快照。
  - leader/follower 全量同步只负责更新当前仓位缓存和当前仓位表，不直接记录仓位历史。
  - 独立仓位历史 poller 每 2 分钟遍历 enabled config，并对当前 leader/follower/pending 涉及的 asset 全量写入 `position_history_poller` 快照。
  - config 创建并完成首次同步后，为当前已有 asset 写一组 baseline 快照。
  - pending 变化不作为仓位历史的触发源；pending 字段只随上述快照保存当时状态，挂单生命周期继续由订单/pending 状态表达。
- 新增查询 API：
  - `GET /api/copy-trading/configs/{config_id}/position-history?asset_id=...&start=...&end=...&normalized=false&limit=2000`
  - `GET /api/copy-trading/configs/{config_id}/position-assets` 返回该 config 可选 asset，来源为 `copy_trading_config_assets`；该表只由历史快照写入和迁移回填维护，不合并当前内存仓位/pending。
  - 鉴权复用现有 `_assert_config_access`。
  - 返回固定 UTC+8 字符串时间；每个点同时返回 raw 字段和用于画图的 `leader_value` / `follower_value`。
  - `normalized=true` 时 `leader_value = leader_position * share_ratio`，`follower_value = follower_position`；`false` 时两者均为原始仓位。
- 前端在跟单配置页内接入：
  - 将当前“持仓”按钮改成展开式曲线面板。
  - 面板包含 asset 选择/输入、时间范围、归一化开关、刷新按钮。
  - 使用已有 `recharts` 画 leader/follower 两条线；tooltip 展示原始仓位、ratio、pending、source、订单/tx 信息。
  - 没有历史点时显示空态；查询失败只影响当前面板。

## Test Plan
- 后端：
  - `python3 -m compileall -q backend/main.py backend/src`
  - 静态确认迁移脚本没有接入 `run_auth_migrations()`。
  - 单测或轻量脚本覆盖 history 查询格式化、归一化计算、limit/start/end 过滤。
- 前端：
  - `npm run build`
  - 手工检查配置页展开/收起、asset 切换、时间段切换、归一化开关、空态和失败态。
- 业务手工验证：
  - 新建/同步配置后能看到 baseline 点。
  - enabled leader BUY/SELL 后能落 `leader_signal` 快照；disabled config 不产生 leader 快照。
  - follower 下单入口不产生 `follower_order_result` 快照。
  - follower WS `trade CONFIRMED` 后能落 `follower_trade_confirmed` 快照；matched-on-post 单不重复更新仓位但仍记录 confirmed 快照。
  - leader/follower 轮询同步不直接写仓位历史；2 分钟 history poller 能全量落 `position_history_poller` 快照。
  - 同一个 follower 跟多个 leader 时，每个 config 查询仍只返回该 config 的 leader + 同一 follower 钱包真实仓位。

## Assumptions
- follower 曲线展示钱包在该 asset 的真实总仓位，不做“该 config 贡献仓位”归因。
- 历史数据从上线后开始记录，不从现有 `copy_trading_orders` 回填。
- `raw_context` 用 `TEXT` 存 JSON 字符串，避免引入 MySQL JSON 兼容性风险。
- 归一化只对 leader 线应用 `share_ratio`，follower 线保持真实仓位。

# 策略多实例与配置管理设计

## 目标

支持 `strategy_weather_sweep` 策略进程管理多个实例，每个实例绑定不同钱包、使用不同参数。用户通过前端创建/管理策略实例，无需重启服务。其他策略后续参照相同模式扩展。

---

## 现状

```
一个策略进程 = 一个实例 = 一个钱包 = 一套参数（env 写死）
```

- 参数从环境变量读取，运行时不可变
- 要给新钱包跑同一策略，只能起新进程
- 前端无法管理策略配置
- 没有订单记录表，无法追溯执行历史

---

## 目标架构

```
一个策略进程 = N 个实例 = N 个钱包 × N 套参数（DB 驱动）

前端 CRUD → strategy_instances 表 → 策略进程动态加载
                                         │
                                    信号到达时
                                         │
                              ├→ 实例1（钱包A, 份额100）
                              ├→ 实例2（钱包B, 份额50）
                              └→ 实例3（钱包C, 份额200）
                                         │
                                    各自独立下单
                                         │
                                         ▼
                                  strategy_orders 表
```

---

## 命名规范

| 层级 | 概念 | 命名 | 说明 |
|------|------|------|------|
| 信号层 | 一条信号记录 | signal | 信号源检测到并广播的一条记录 |
| 信号层 | 信号唯一标识 | signal_id | 全局唯一，跨表关联用 |
| 信号层 | 信号类型 | signal_type | sweep / leader_buy / no_longer_possible 等 |
| 策略层 | 一次完整执行 | event | 从信号触发到生命周期结束 |
| 策略层 | 执行唯一标识 | event_id | UUID，标识一次 event |
| 策略层 | 执行中的步骤 | step | event 内的每一步 |
| Polymarket | 市场组 | event_slug | Polymarket 术语，不改 |

### 信号表：weather_orderbook_signals（重命名自 signal_weather_events）

```sql
CREATE TABLE weather_orderbook_signals (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  signal_id VARCHAR(512) NOT NULL COMMENT '信号唯一标识（原 notification_key）',
  signal_type ENUM('sweep', 'no_longer_possible', 'market_resolved', 'event_started')
      NOT NULL COMMENT '信号类型（原 event_type）',
  occurred_at DATETIME(3) NOT NULL COMMENT '信号发生时间 UTC',

  -- Polymarket 市场上下文
  event_slug VARCHAR(255) NOT NULL,
  market_slug VARCHAR(255) NULL,
  token_id VARCHAR(100) NULL,
  outcome ENUM('yes', 'no') NULL,

  -- 天气特有字段
  city VARCHAR(100) NOT NULL,
  city_slug VARCHAR(100) NOT NULL,
  direction ENUM('highest', 'lowest') NOT NULL,
  local_date DATE NOT NULL,
  temperature_label VARCHAR(100) NULL,

  -- 主监控器快照
  main_market_slug VARCHAR(255) NULL,
  main_temperature_label VARCHAR(100) NULL,
  main_outcome ENUM('yes', 'no') NULL,
  is_from_main TINYINT(1) GENERATED ALWAYS AS (main_market_slug <=> market_slug) STORED,

  -- 元数据
  status ENUM('monitoring', 'resolved', 'exhausted') NULL,
  reason VARCHAR(255) NULL,
  payload JSON NOT NULL COMMENT '订单簿快照等详情',
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),

  PRIMARY KEY (id),
  UNIQUE KEY uq_signal_id (signal_id),
  KEY idx_event_time (event_slug, occurred_at DESC, id DESC),
  KEY idx_city_date (city_slug, direction, local_date),
  KEY idx_recent (occurred_at DESC, id DESC)
) COMMENT='天气信号记录';
```

### 策略事件表：weather_sweep_events（记录执行过程）

```sql
CREATE TABLE weather_sweep_events (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,

  -- ① 配置相关：谁、用什么钱包、什么配置
  owner_user_id INT NOT NULL COMMENT '所属用户',
  proxy_wallet VARCHAR(128) NOT NULL COMMENT '执行钱包',
  config_id BIGINT UNSIGNED NOT NULL COMMENT '关联 weather_sweep_configs.id',
  config_snapshot JSON NULL COMMENT '执行时的配置快照',

  -- ② event 上下文：这次执行的市场信息（同一 event 内所有 step 相同）
  event_id CHAR(36) NOT NULL COMMENT '一次完整执行的 UUID',
  signal_id VARCHAR(512) NULL COMMENT '触发信号（关联 weather_orderbook_signals.signal_id）',
  token_id VARCHAR(128) NULL COMMENT '交易的 token',
  market_slug VARCHAR(255) NULL COMMENT 'Polymarket market slug',
  event_slug VARCHAR(255) NULL COMMENT 'Polymarket event slug（市场组）',

  -- ③ 执行记录本身：这一步做了什么
  step VARCHAR(64) NOT NULL COMMENT '步骤类型',
  sequence_no INT UNSIGNED NOT NULL COMMENT '步骤序号（event 内递增）',
  detail JSON NOT NULL COMMENT '步骤数据',
  occurred_at DATETIME(3) NOT NULL,

  PRIMARY KEY (id),
  UNIQUE KEY uq_event_seq (event_id, sequence_no),
  KEY idx_owner_wallet (owner_user_id, proxy_wallet, occurred_at DESC),
  KEY idx_config_event (config_id, event_id),
  KEY idx_token (token_id, occurred_at DESC),
  KEY idx_event_slug (event_slug, occurred_at DESC),
  KEY idx_occurred (occurred_at DESC)
) COMMENT='Weather Sweep 执行事件日志（一个 event = 多个 step）';
```

**设计要点：**
- `event_id`：UUID，一次完整执行生命周期的唯一标识
- `config_id`：对应哪个配置实例触发的
- `signal_id`：触发该 event 的信号（可关联 weather_orderbook_signals 表查详情）
- `step`：该 event 中的步骤类型
- `sequence_no`：步骤在 event 内的顺序号，保证时间线有序
- `detail`：JSON，各 step 数据不同（见下方详细设计）

### weather_sweep step 详细设计

根据策略状态机 `idle → entry_working → exit_working → closed`，完整事件流如下：

#### 1. `signal_received` — 收到 sweep 信号，开始一轮新执行

```json
{
  "signal_id": "city-temp:0xabc:1724500321000",
  "token_id": "0xabc123...",
  "market_slug": "will-high-temperature-in-nyc...",
  "event_slug": "higher-temperature-in-new-york-...",
  "city": "New York",
  "direction": "higher"
}
```

#### 2. `buy_placed` — BUY 订单已提交

```json
{
  "order_id": "0x1234...",
  "price": "0.99",
  "size": "100",
  "actual_size": "100",
  "max_affordable": "120"
}
```

#### 3. `buy_failed` — BUY 下单失败（资金不足/API 错误）

```json
{
  "reason": "no_cash" | "api_error",
  "requested_size": "100",
  "available_cash": "50"
}
```

#### 4. `buy_filled` — BUY 订单成交（立即成交/部分成交回报）

```json
{
  "order_id": "0x1234...",
  "filled_size": "100",
  "total_position": "100",
  "fill_price": "0.99"
}
```

#### 5. `risk_started` — 风控监控启动

```json
{
  "entry_price": "0.99",
  "stop_loss_ratio": "0.60",
  "stop_loss_price": "0.594"
}
```

#### 6. `entry_timeout` — 入场超时，撤销未成交部分

```json
{
  "wait_ms": 30000,
  "order_id": "0x1234...",
  "filled_size": "80",
  "cancelled_size": "20",
  "final_position": "80"
}
```

#### 7. `tick_detected` — BBO 中检测到 tick_size=0.001

```json
{
  "tick_size": "0.001",
  "source": "bbo_update"
}
```

#### 8. `tick_verified` — HTTP 校验确认 tick=0.001

```json
{
  "token_id": "0xabc123...",
  "confirmed": true,
  "verify_latency_ms": 120
}
```

#### 9. `sell_placed` — SELL 退出订单已提交

```json
{
  "order_id": "0x5678...",
  "price": "0.999",
  "size": "80",
  "reason": "tick_exit"
}
```

#### 10. `sell_filled` — SELL 订单成交

```json
{
  "order_id": "0x5678...",
  "filled_size": "80",
  "fill_price": "0.999",
  "remaining_position": "0"
}
```

#### 11. `stop_loss_triggered` — 止损触发，强制卖出

```json
{
  "current_price": "0.55",
  "entry_price": "0.99",
  "loss_ratio": "0.44",
  "threshold": "0.60",
  "sell_order_id": "0x9999...",
  "sell_price": "0.01",
  "sell_size": "100"
}
```

#### 12. `event_closed` — 本次 event 结束

```json
{
  "reason": "tick_exit" | "stop_loss" | "timeout_no_fill" | "buy_failed",
  "total_bought": "80",
  "total_sold": "80",
  "entry_price": "0.99",
  "exit_price": "0.999",
  "pnl": "0.72",
  "duration_ms": 190000
}
```

---

### 典型事件序列

**正常 tick_exit 路径：**
```
signal_received → buy_placed → buy_filled → risk_started
→ tick_detected → tick_verified → sell_placed → sell_filled → event_closed
```

**超时部分成交路径：**
```
signal_received → buy_placed → buy_filled(部分) → risk_started
→ entry_timeout → tick_detected → tick_verified → sell_placed → sell_filled → event_closed
```

**止损路径：**
```
signal_received → buy_placed → buy_filled → risk_started
→ stop_loss_triggered → event_closed
```

**无资金路径：**
```
signal_received → buy_failed → event_closed
```

**超时未成交路径：**
```
signal_received → buy_placed → entry_timeout(成交0) → event_closed
```

### container.py 核心改动

```python
class StrategyContainer:
    def __init__(self, strategy_class, signal_sources, strategy_type):
        self._strategy_class = strategy_class
        self._signal_sources = signal_sources
        self._strategy_type = strategy_type
        self._instances: dict[int, BaseStrategy] = {}  # instance_id → strategy

    async def start(self):
        # 1. 启动信号源 WS（共享，只连一次）
        for source in self._signal_sources:
            client = SignalWSClient(url=source.url, adapter=source.adapter)
            task = asyncio.create_task(client.listen(self._dispatch_signal))
            self._ws_tasks.append(task)

        # 2. 从 DB 加载所有 enabled 实例
        configs = InstanceManager.load(self._strategy_type)
        for cfg in configs:
            await self._start_instance(cfg)

    async def _start_instance(self, cfg):
        strategy = self._strategy_class()
        ctx = StrategyContext(
            executor=OrderExecutor(proxy_wallet=cfg.proxy_wallet),
            state_store=MySQLStateStore(),
            config=cfg.config,
            proxy_wallet=cfg.proxy_wallet,
            event_id=str(uuid.uuid4()),
        )
        await strategy.start(ctx)
        self._instances[cfg.id] = strategy

    async def _dispatch_signal(self, signal):
        for instance_id, strategy in self._instances.items():
            try:
                await strategy.on_signal(signal)
            except Exception:
                logger.exception("Instance %d error", instance_id)
```

### CRUD 接口

```
POST   /api/strategy/instances
  Body: {strategy_type, proxy_wallet, config}
  → 插入 DB + 通知对应策略进程热加载

GET    /api/strategy/instances
  Query: ?strategy_type=weather_sweep
  → 返回当前用户的所有实例

PUT    /api/strategy/instances/:id
  Body: {config?, enabled?}
  → 更新 DB + 通知策略进程热更新参数或启停

DELETE /api/strategy/instances/:id
  → 标记删除 + 通知策略进程停止该实例
```

### 热更新机制

策略进程定时（每 30 秒）或通过内部 HTTP 端点接收更新通知：

```
Gateway CRUD → POST http://strategy-process:8003/internal/reload
                → container 重新从 DB 加载配置
                → diff：新增的启动、删除的停止、参数变了的重建
```

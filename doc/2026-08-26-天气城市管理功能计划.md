# 天气城市管理功能计划

## 目标

为天气信号模块增加城市 CRUD 管理能力，支持在前端动态添加/编辑/启用/禁用/删除监听城市，修改后无需重启服务即可生效。

## 现状

- `weather_cities` 表通过 `schema.sql` 的 INSERT 语句预置了 50 个城市
- `WeatherCityRepository.list_enabled()` 在服务启动时加载启用的城市列表
- 城市列表加载后固定在内存中，只有日切 rollover 时刷新市场发现，不会重新读取城市列表
- 前端 `GET /api/weather/cities` 返回的是运行时内存中的城市状态（含市场发现结果），不是数据库原始配置

## 方案设计

### 一、后端 API

在 `signal_weather/api.py` 中新增管理路由（需 root 权限）：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/weather/cities/admin` | 列出所有城市（含 disabled），返回数据库原始字段 |
| POST | `/api/weather/cities/admin` | 新增城市 |
| PUT | `/api/weather/cities/admin/{id}` | 编辑城市配置 |
| DELETE | `/api/weather/cities/admin/{id}` | 删除城市（物理删除，因为无外键依赖） |
| POST | `/api/weather/cities/reload` | 触发信号服务热重载城市列表 |

#### 请求体结构（POST/PUT）

```json
{
  "city_name": "Berlin",
  "city_slug": "berlin",
  "timezone": "Europe/Berlin",
  "has_highest_market": true,
  "has_lowest_market": false,
  "monitor_highest": true,
  "monitor_lowest": false,
  "enabled": true,
  "sort_order": 510
}
```

#### 校验规则

- `city_slug` 全局唯一
- `timezone` 必须是合法 IANA 时区
- `monitor_highest=true` 要求 `has_highest_market=true`
- `monitor_lowest=true` 要求 `has_lowest_market=true`
- 启用的城市必须至少监听一个方向

### 三、热重载机制

在 `WeatherService` 中新增 `reload_cities()` 方法：

```python
async def reload_cities(self) -> None:
    """从数据库重新加载城市列表，重建监控引擎"""
    new_cities = await self.dao.list_enabled()
    # 停止旧的 coordinator
    await self.coordinator.stop()
    # 用新城市列表重建
    self.cities = new_cities
    self._city_by_name = {city.name: city for city in new_cities}
    self.coordinator = WeatherEngine(
        new_cities,
        WeatherDiscovery(self.market_client),
        self._on_weather_event,
        on_broadcast=self._broadcast_event,
    )
    await self.coordinator.start()
    await self.refresh_signal_counts()
    await self._warm_signal_cache()
```

`POST /api/weather/cities/reload` 调用此方法。

### 四、前端

在「天气监控」页面增加入口，新建 `WeatherCityAdmin.tsx` 组件：

**页面结构**：
- 顶部：「新增城市」按钮 + 「应用更改（重载）」按钮
- 表格：所有城市列表，每行显示：
  - 城市名 | slug | 时区
  - 最高温市场（有/无） | 最低温市场（有/无）
  - 监听最高温（开关） | 监听最低温（开关）
  - 启用状态（开关）
  - 排序值
  - 操作：编辑 / 删除
- 新增/编辑使用弹窗表单

**交互流程**：
1. 用户增/改/删城市 → 数据库立即更新
2. 用户点击「应用更改」→ 调用 reload API → 信号服务热重载
3. 提示"重载成功，新配置已生效"

### 六、不做的事

- 不改 `weather_cities` 表结构（现有字段足够）
- 不做城市批量导入（手动一个个加够用）
- 不做软删除（无外键引用，物理删除即可）
- `schema.sql` 的种子数据保持不变（新环境初始化用）

### 七、执行顺序

1. 后端 DAO 层：新增 CRUD 方法
2. 后端 Service 层：新增 reload_cities()
3. 后端 API 层：新增管理路由
4. 前端：城市管理页面 + 路由接入
5. 测试：增/改/删城市 → 重载 → 验证监控生效

# 天气监控前端模块迁移计划

## 背景

将 `/Users/liutianshi/Desktop/polymarket/code/strategy/weather-leader-monitor/frontend` 的天气监控界面，
作为一个新的页面模块集成到 WeatherTaker 前端（左侧导航栏新增第6个入口）。

## 技术差异

| | 源项目 (weather-leader-monitor) | 目标项目 (WeatherTaker) |
|---|---|---|
| 框架 | Vue 3 + Element Plus | React 19 (无 UI 库) |
| 语言 | JavaScript | TypeScript |
| 构建 | Vite + Vue plugin | Vite + React |
| 组件 | .vue SFC | .tsx |

**结论：不能直接复制 .vue 文件，需要用 React + TypeScript 重写 UI 逻辑。**

## 源前端包含的功能

1. **城市监控表格** (App.vue)：展示各城市天气市场监控状态、当前候选市场、温度标签、订单簿摘要
2. **实时订单簿** (MarketOrderbook.vue)：展开某市场后显示 bids/asks 深度
3. **事件通知时间线** (EventNotificationTimeline.vue)：某个事件下的 Telegram 通知历史
4. **最近通知列表** (RecentNotifications.vue)：全局最新通知流
5. **Telegram 配置** (App.vue 内)：配置 bot_token 和 chat_ids
6. **SSE 实时推送**：城市状态和订单簿变化通过 SSE 实时刷新

## 对应的后端 API（已迁移完成）

- `GET /api/weather/cities` — 获取城市监控状态
- `GET /api/weather/orderbook/:tokenId` — 获取订单簿快照
- `GET /api/weather/events/:eventSlug/notifications` — 事件通知历史
- `GET /api/weather/notifications/recent` — 最近通知
- `GET /api/weather/cities/stream` — SSE 实时推送（城市状态）
- `GET /api/weather/orderbook/:tokenId/stream` — SSE 实时推送（订单簿）

## 实施步骤

### 第1步：创建页面文件

新建 `frontend/src/pages/WeatherMonitor.tsx`，作为天气监控模块的主页面。

### 第2步：注册路由和导航

在 `App.tsx` 中：
- `Page` 类型新增 `'weather'`
- 左侧导航栏新增"天气监控"入口（放在"性能监控"之前或之后）
- 新增条件渲染 `<WeatherMonitor />`

### 第3步：实现 API 调用层

在 `frontend/src/api.ts` 中新增天气相关的 fetch 函数：
- `fetchWeatherCities()`
- `fetchWeatherOrderbook(tokenId)`
- `fetchWeatherEventNotifications(eventSlug, options)`
- `fetchWeatherRecentNotifications(options)`

### 第4步：实现子组件

按源项目的 Vue 组件对应创建 React 组件（可放在 pages/WeatherMonitor/ 目录或 components/ 下）：

| 源 Vue 组件 | 目标 React 组件 | 功能 |
|---|---|---|
| App.vue (表格部分) | `WeatherMonitor.tsx` 主体 | 城市监控表格 + 搜索 |
| MarketOrderbook.vue | `WeatherOrderbook.tsx` | 实时订单簿展示 |
| EventNotificationTimeline.vue | `WeatherTimeline.tsx` | 事件通知时间线 |
| RecentNotifications.vue | `WeatherNotifications.tsx` | 最近通知列表 |

### 第5步：实现 SSE 实时连接

参考源项目 App.vue 中的 EventSource 逻辑，在 React 中使用 `useEffect` + `EventSource` 实现：
- 城市状态实时刷新
- 订单簿实时更新

### 第6步：样式适配

源项目使用 Element Plus 组件（el-table、el-collapse 等）。目标项目无 UI 库，需要：
- 用原生 HTML table + 现有项目的暗色主题 CSS 风格实现表格
- 折叠面板用简单的 state toggle 实现
- 保持与现有页面（Account、CopyTrading 等）的视觉一致性

## 不迁移的部分

- **Telegram 配置** — 该功能属于 weather-leader-monitor 项目独有，WeatherTaker 暂无 Telegram 通知模块

## 依赖

- 后端 `weather_orderbook` 模块已迁移完成（本次会话已完成）
- 后端 API 路由需要在 `main.py` 中注册 `weather_orderbook_router`
- 无需新增前端第三方依赖

## 风险点

1. 后端 `weather_orderbook/api.py` 中使用了 SSE（StreamingResponse），需确认当前项目前端是否已有 SSE 处理模式
2. 后端 `dao.py` 使用 asyncmy 连接池，需在 main.py lifespan 中初始化该连接池并传入 service
3. 数据库需要 `weather_cities` 和 `weather_notifications` 两张表的 DDL
